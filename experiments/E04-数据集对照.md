# 实验 E04 · 固定全部参数，只换数据集

> ⬜ **状态：方案已就绪，待跑**（需要有 GPU 的环境）
> 建立：2026-09-16
>
> ⭐ **这是本库最重要的一组实验** —— E01~E03 全在改参数，**一次改数据的都没有**，
> 所以本库一直关注的判断「**数据质量 ≫ 超参数**」**从未被检验过**。E04 就是来补这个的。

---

## 一 · 假设

> **一句话**：我**只换数据集、其余一切不动**，预期 **输出质量会明显变化**；
> 若变化幅度**大于** E01~E03「只改参数」带来的变化，则支持「数据 ≫ 参数」。

- **本实验属于哪一类**：
  - [x] **改数据**（数据集内容 / 配比 / 清洗规则）
  - [ ] 改参数
  - [ ] 其他

---

## 二 · 变量（**设计要点全在这一节**）

| | 值 |
|---|---|
| **自变量（只改这一个）** | **数据集** |
| 对照组 | A 组：`alpaca-clean-500条` 抽 **194** 条 |
| 实验组 | B 组：`qa-general-194条` 全部 **194** 条 |
| 控制变量 | `lora_rank: 8` · `lora_alpha: 16` · `learning_rate: 2.0e-4` · `num_train_epochs: 3` · `batch_size: 2` · `grad_accum: 4` · `cutoff_len: 1024` · `template: qwen` · 基座 `Qwen3-8B` · **条数都是 194** |

### ⚠️ 三个设计要点（不满足就没意义）

1. **两边条数必须相同（都 194）**
   若拿 194 条 vs 500 条比，就**混淆了「数据内容」和「数据条数」**两个变量 —— 归因不成立。
   → 所以要从 `alpaca-clean-500条` 里**抽 194 条**，而不是直接用它的 500 条。

2. **抽样必须确定**（可复现）
   → `scripts/datasets/make_e04_datasets.py` 用**固定种子**抽样，产出固定文件。

3. **除了数据集，其余一个都不许改**
   → 两个配置文件应当**逐行相同，只有 `dataset:` 和 `output_dir:` 两行不同**
   （`dataset` 是自变量；`output_dir` 不同只为避免两组产出互相覆盖，不影响训练本身）。
   跑之前先 `diff` 一下确认。

### 为什么选这两个数据集

| | A 组（`alpaca-clean`） | B 组（`qa-general-194条`） |
|---|---|---|
| 来源 | 公开数据集 `yahma/alpaca-cleaned` | 开源 100 + 本地模型生成 94 |
| 语言 | 100% 英文 | **48% 中文 / 52% 英文（意外混采）** |
| 已知缺陷 | 抽样偏倚（取连续前 550 条） | 中英混采未设计 · 生成部分是单模型蒸馏 · 未去重 · 有 3–7 字符的退化输出 |
| 直觉判断 | 公认高质量 | 缺陷更多 |

> ⚠️ **「A 质量更高」是直觉判断，不是本库已证的结论。**
> 所以本实验**不给结论定方向** —— 只问「换数据会不会让输出变化」。
> 若 B 反而更好，那也是有效结果，**照实记录**。

## 八 · 跑之前的环境准备

```bash
# 1. 生成两个同条数的数据集（确定性）
python scripts/datasets/make_e04_datasets.py
#    → datasets/alpaca-clean-500条/E04-A组-194条.json   （A 组，从 500 条里抽 194）
#    B 组直接用 datasets/qa-general-194条/my_dataset.json（本来就是 194 条，无需生成）

# 2. 确认配置只差两行（dataset / output_dir）
diff configs/E04-A组-alpaca194.yaml configs/E04-B组-qa194.yaml

# 3. 训练（两次）
llamafactory-cli train configs/E04-A组-alpaca194.yaml
llamafactory-cli train configs/E04-B组-qa194.yaml

# 4. 评测 —— 见 experiments/E05-人工判断.md
```

### 💡 评测时不必先合并权重 / 导出 GGUF

vLLM 可以直接挂载 LoRA 适配器，**同一份基座 + 两个 adapter 同时起服务**：

```bash
vllm serve <基座模型路径> \
    --lora-modules e04-a=<E04 A 组 output_dir> \
                   e04-b=<E04 B 组 output_dir> \
    --port 8001
```

调用时用 `model` 字段选适配器名即可（`"model": "e04-a"` / `"e04-b"`）。
→ **省掉「合并权重 → 导出 GGUF → Ollama 导入」三步**，直接进入评测。

> ⚠️ 这条只影响**评测步骤的便捷性**，不影响训练本身。
> 好处是能**复用同一个基座进程**，两组对比时基座部分完全一致。

> ⚠️ `configs/` 里的 `model_name_or_path` 与 `output_dir` 是**原环境（AutoDL）的路径**，
> 直接跑会失败，**需要改成你自己的路径**。
