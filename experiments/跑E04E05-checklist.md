### 1.3 ⭐ 探针：模型「能起来」≠「能答得了」

> 📌 **这一条是从坑里学来的**：某次健康检查全绿（数据库 ok / 缓存 ok），
> 发一条真实业务请求**立刻 500**。**没有探针，你会把"环境问题"读成"模型质量差"。**

```bash
# 起一个端点，然后发一次真实请求
curl -s <你的端点>/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"<你的模型名>","messages":[{"role":"user","content":"说一句你好"}],"max_tokens":16}'
```

> **怎么知道它成了**：返回里有**非空的中文回答**。
> ⛔ HTTP 200 不算成；返回体里是 `{"error": ...}` 不算成。
> **探针没过就不要往下跑** —— 后面的"失败"会分不清是环境还是效果。

## 二 · E04 · 两组训练

### 2.0 前置：先把两组数据集造出来

```bash
python scripts/datasets/make_e04_datasets.py --full <全量 51760 条的文件路径>
```

> 该文件**不在仓库里**（42 MB）。生成方式见脚本文件头。
> 生成后放仓库根目录，或加 `--full <路径>` 指定。

**脚本会自己打印自检**，你要看到：

```
✅ 条数相同：各 194 条
ℹ️ instruction 均长：A=63.1  B=84.9
✅ 设计与自检通过
```

> **怎么知道它成了**：① 两行「条数相同：各 194 条」；② **A 与 B 的均长明显不同**
> （B 来自有偏区块，应更长）。
> ⛔ **如果 A、B 均长一样** → 抽样出问题了，**停下来查**，别拿去跑。
> **为什么看均长**：它是本实验**自变量的体现**。两组都一样 = 自变量没生效 = 实验白做。

### 2.1 ⭐ 前置：确认两配置只差两行

```bash
diff configs/E04-A组-random随机194.yaml configs/E04-B组-front550前段194.yaml
```

> **怎么知道它成了**：diff 输出里**只有 `dataset:` 与 `output_dir:` 两行**。
> ⛔ **多出任何一行都不许开跑** —— E04 能归因的前提就是"只改了一个变量"。

### 2.2 注册数据集

把这两条加进 LLaMA-Factory 的 `data/dataset_info.json`：

```json
"e04_a_random194":   { "file_name": "E04-A组-194条.json" },
"e04_b_front550_194": { "file_name": "E04-B组-194条.json" }
```

并把两个 json 文件复制到那个 `data/` 目录下。

> **怎么知道它成了**：训练启动后，日志里的 `Num examples` 应显示 **194**。
> ⛔ 显示别的数字 ⇒ 注册错了文件。

### 2.3 开跑（两组）

> ⚠️ **先改路径**：`configs/` 里的 `model_name_or_path` 与 `output_dir` 是
> **原环境（AutoDL）的路径**，直接跑会失败。

```bash
# ⚠️ 不要接 | tail —— 管道会缓冲，看不到进度
llamafactory-cli train configs/E04-A组-random随机194.yaml > /tmp/e04-a.log 2>&1 &
tail -f /tmp/e04-a.log          # 另开一条看进度
```

跑完 A 组再跑 B 组。**两组之间不要改任何其它设置。**

> **怎么知道它成了**：① 日志出现 `train_runtime`；② 产出目录里有 `all_results.json`。
> **两组都要记下**：`train_loss`（末值）、`train_runtime`、**总步数**。
> 📌 总步数应等于 `ceil(194 ÷ (batch × grad_accum)) × 3` —— **算一遍对一下**。

### 2.4 ⚠️ 两组的差异必须可见

```bash
python3 -c "
import json
for g,p in [('A','<A的output_dir>/all_results.json'),('B','<B的output_dir>/all_results.json')]:
    d=json.load(open(p)); print(g, 'loss=',d['train_loss'],'runtime=',d['train_runtime'])
"
```

> **怎么知道它成了**：两组的 loss **不一样**。
> ⛔ **如果两组 loss 一模一样** → 极可能**两组跑的是同一份数据**，
> 或者第二组覆盖了第一组。**停下来查**，别往下走。
> 📌 依据：重复 N 次的实验，必须有东西守着「重复之间确实不同」。

## 三 · E05 · 评测（三组对比）

### 3.0 ⚠️ 这一步最容易白做 —— 先读

> 📌 **本库已经废过一次评测**：50 条里 24 条两边回答全空，且**两边跑的是同一个模型**
> （脚本里两处都传 `"qwen3:8b"`）。**基准和实验组同名 ⇒ 比的是自己跟自己。**
> 详见 `results/README.md`。

### 3.1 准备两个模型端点

E05 需要**能同时访问两个不同的模型**。两种做法：

| 做法 | 说明 |
|---|---|
| **A · vLLM 挂 LoRA**（推荐） | `vllm serve <基座> --lora-modules e04a=<A的adapter> e04b=<B的adapter> --port 8001`<br>**省掉「合并权重 → 导出 GGUF → Ollama 导入」三步** |
| **B · Ollama** | 先 `llamafactory-cli export --export_ollama true`，再 `ollama create`，两组各建一个模型 |

### 3.2 ⭐ 前置探针：确认两个端点**真的不同**

> ⛔ **不做这一步，后面全白跑。** 这是本库用一次废评测换来的。

```bash
for m in e04a e04b; do
  echo -n "$m: "
  curl -s <端点>/v1/chat/completions -H "Content-Type: application/json" \
    -d "{\"model\":\"$m\",\"messages\":[{\"role\":\"user\",\"content\":\"用一句话说明什么是GPU\"}],\"max_tokens\":32}"
done
```

> **怎么知道它成了**：两条回答**不一样**。
> ⛔ **两条一模一样 ⇒ 两个端点其实是同一个模型**（adapter 没加载 / 打错端口）。
> **停下来排查，绝对不要往下跑。**

### 3.3 生成对照样本（**三组**）

```bash
# 组 1：基座 vs A   ｜  组 2：基座 vs B   ｜  组 3：A vs B（← 这组才是 E04 的直接答案）
python scripts/eval/make_comparison_samples.py \
  --prompts datasets/alpaca-clean-500条/my_test_dataset.json \
  --model-a <基座> --model-b <A> --backend openai --base-url <端点> \
  --temperature 0.0 --out results/E05-基座vsA

python scripts/eval/make_comparison_samples.py \
  --prompts datasets/alpaca-clean-500条/my_test_dataset.json \
  --model-a <基座> --model-b <B> --backend openai --base-url <端点> \
  --temperature 0.0 --out results/E05-基座vsB

python scripts/eval/make_comparison_samples.py \
  --prompts datasets/alpaca-clean-500条/my_test_dataset.json \
  --model-a <A> --model-b <B> --backend openai --base-url <端点> \
  --temperature 0.0 --out results/E05-AvsB
```

> **脚本会打印三道检查**，你要看到：
> ```
> ① 两边都空   : 0 / 50        ← ⛔ 不为 0 就要排查
> ② 逐字相同   : 0 / 50        ← ⛔ 不为 0 就要排查（两个端点可能是一个模型）
> ③ 有效可判   : 50 / 50
> ```
> ⛔ **第 ①② 项任一不为 0，先排查，不要拿这份结果去判。**

### 3.4 人工判断

打开 `results/E05-*.md`，逐条填「判断」：

> ⛔ 把 `both_bad` 算进「平局」= 重复本库那次废评测的错误。

## 五 · 本库已知的坑（照着避开）

| # | 坑 | 怎么避 |
|---|---|---|
| 1 | **两边跑的是同一个模型** | §3.2 的探针（本库真踩过，废掉一次评测） |
| 2 | **把「预期结果」当「结果」记** | 结果表里**只填跑出来的数**；推算/举例标 `预计` 且**不混进同一张表** |
| 3 | **把"内容更全"当"实际跑过的版本"** | 判断依据看**产物**（checkpoint 目录），不看文件完整度 |
| 4 | **「训练 loss」与「最后一条逐步记录」不是同一个量** | 引用时说清是哪一个（本库 exp1：0.5603 vs 0.8108） |
| 5 | **同一组配置连跑两次，产物会混淆** | 记清楚用的是哪个 `output_dir`、哪个 checkpoint |
| 6 | **启用了早停却没配验证集** | 早停段**必须配 `val_size` 或 `eval_dataset`** 才生效（本库踩过：写了但从未触发） |
| 7 | **用脚本批量改文档** | 用「唯一子串替换」或整文件重写；改完**复核结构**（围栏配对/表格列数） |
