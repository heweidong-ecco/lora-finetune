# 实验 E02 · 把 LoRA rank 从 8 提到 16

> 由 `mlflow.db` 真库 + `configs/exp2_rank16.yaml` 重建，2026-09-16。

---

## 一 · 假设

> **一句话**：我改 **`lora_rank` 8 → 16**，预期 **模型能学到更多（loss 更低）**，
> 因为 **rank 越大适配器容量越大**。

- **本实验属于哪一类**：
  - [ ] 改数据
  - [x] **改参数**（lora_rank）
  - [ ] 其他

## 二 · 变量

| | 值 |
|---|---|
| **自变量**（只改这一个） | **`lora_rank`: 8 → 16**（连带 `lora_alpha`: 16 → 32，按「alpha = 2×rank」惯例） |
| 对照组 | **E01 baseline**（`configs/exp1_baseline.yaml`） |
| 控制变量 | 数据集（500 条同一份）、lr 2e-4、epochs 3、bs 2、ga 4、cutoff_len 1024、template qwen、基座 Qwen3-8B |

> ⚠️ 严格说这里**改了 2 个**（rank 与 alpha）。但 alpha 是跟着 rank 按固定比例走的，
> 属于同一操作，可接受；**若日后 alpha 有独立变化，必须拆成两组。**

**对照样例**：❌ **没有**

> ⚠️ **loss 变高 ≠ 变差。** rank 增大后，同样的数据上 loss 反而升高，
> 常见的解释是**过拟合或容量冗余**，但**本实验没有任何输出质量证据能判定**。
> 目前只能说：**这次调参让 loss 变高了、变慢了，输出质量未知。**

## 六 · 结论

- **假设成立吗**：❌ **不成立**（预期 loss 更低，实际更高）
- **一句话结论**：**rank 8 → 16 在本数据集上没有任何收益**，loss 高 51%、耗时多 66%
- **意外发现**：
  - 按 `configs/best_lora_config.yaml` 里自己写的判断标准——
    「**loss 反而更高 → 该参数改动方向错误，保持原参数**」——
    这里的结论应当是**保持 rank 8**，而且 rank 8 的适配器还**更小、加载更快**
  - ⚠️ **但 MLflow 里根本没记录 `lora_rank`**（见 `experiments/README.md` §三），
    所以这条结论**只能靠比对两个 yaml 文件**得出，**无法从实验管理系统里复核**
