## 二 · 任务定义

- **要模型学会什么**：**代码补全（Fill-in-the-Middle）**
- **输入格式**：Alpaca 三字段，`instruction` 固定为「补全以下Python代码，保持代码风格一致」
- **输出格式**：补齐的代码片段

**一条样本长什么样**：

```
instruction: 补全以下Python代码，保持代码风格一致
input:       class MockResponse:
                 """Wraps a `httplib.HTTPMessage` to mimic a `urllib.addinfourl`."""
                 ...（代码上文）
output:              :param headers: a httplib.HTTPMessage or analogous carrying the headers
                         """
                         self._head...（补全的下文）
```

> 📌 `subprojects/code-completion-lora/README.md` 里还给了 **FIM 原生格式**
> （`<fim_prefix>…<fim_suffix>…<fim_middle>`）作为对比，
> 并说明**实际采用「通义灵码格式」（更简单，推荐）**——即上面这种 instruction/input/output。

## 三 · 构造过程

**提取规则（来自 `extract_code_data.py` 第 18–22 行）：**

| 参数 | 值 |
|---|---|
| `MAX_SAMPLES` | **300**（目标数量）→ **实得 250** |
| `MIN_LINES` | 8（最少代码行数） |
| `MAX_LINES` | 50（最多代码行数） |
| `MIN_CHARS` | 50（最少字符数） |

| 步骤 | 怎么做的 | 产出 | 砍掉 |
|---|---|---|---|
| 1. 取源码 | 从数据源拉 Python 代码 或 扫本地 `site-packages` | — | — |
| 2. 切片段 | 按 8–50 行、≥50 字符切 | — | 不满足的片段 |
| 3. **语法校验** | **`ast.parse()` 过滤语法错误的片段** ← 这一步是质量关键 | — | 语法不过的 |
| 4. 组样本 | 上文 → `input`，下文 → `output` | **250** | 目标 300，**差 50** |

> ✅ **第 3 步是这个数据集做得好的地方** —— 用 `ast.parse` 做硬性语法检查，
> 而不是靠"看起来像代码"来判定。这比多数教程里的代码数据构造要严谨。

- **清洗规则**：`ast.parse` 语法校验（唯一一道）
- **去重口径**：**未做去重**。复算结果：字面重复 **0 条**（250 个样本两两不同）
- **质检方式**：`subprojects/code-completion-lora/check_quality.py`（脚本自动检查），**无人工抽检**

## 五 · 已知缺陷（**必须写，不许省略**）

### 1. ⚠️ 来源不确定（**最严重的一条**）

见 §一。两个脚本写同一个文件，**没有任何记录说明 250 条出自哪一个**；
本人回忆指向 `local_code_extractor.py`（本机依赖），**但回忆不是记录**。
→ **这直接导致许可证无法判定**，也导致**别人无法精确复现**。

### 2. ⚠️ 代码注释与代码不一致

`extract_code_data.py` 的文件头写着「从 **The Stack** 数据集提取」，
但生效的代码用的是 `codefuse-ai/CodeExercise-Python-27k`；
The Stack 那行**已被注释掉**。README 里也解释了原因（The Stack 是门控数据集，用不了）。
→ **注释是过期信息**，只看注释会得出错误结论。

### 3. ⚠️ 许可证未确认（**若回忆属实，这条比想象的更麻烦**）

| 若来源是 | 许可情况 |
|---|---|
| `codefuse-ai/CodeExercise-Python-27k`（ModelScope） | 查该数据集自己的许可即可，**相对简单** |
| **本机 `site-packages` 的库源码**（← 回忆指向这条） | ⚠️ **第三方库各有各的许可证**（MIT / Apache-2.0 / BSD / **GPL** / 商业许可都有）。<br>`local_code_extractor.py` 只扫 `site-packages[:3]`，**不记录取了哪些库** → **具体构成不可知** |

**本人 2026-09-16 的判断**：原话「**应该没事**」——
即认为这批代码片段零散、体积小、用作训练数据，风险可接受。

> 📌 **记录在案，不作评判。** 但有三点客观事实请知悉：
> 1. **GPL 类许可的代码被再分发**，与 MIT/Apache 的再分发条件不同；
> 2. 本数据集是**公开仓库里的完整数据文件**（250 条，未做来源标注）；
> 3. **无法追溯是哪些库** —— 这一点即使想补救也没有依据。
>
> 👉 **可选的缓解做法**：像 42MB 原始数据那样，**只留数据卡 + 提取脚本，不放数据文件本身**
> （别人可自己跑 `local_code_extractor.py` 得到一份**属于他自己环境**的数据）。
> ⛔ **在确认来源之前，不要对外声称这份数据的许可证。**
